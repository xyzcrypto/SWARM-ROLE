## 2. Bugs found & FIXED in this pass

| # | Severity | Bug | Fix |
|---|---|---|---|
| 1 | Medium | **Password-reset shared the signup rate-limit bucket** (`api/auth/password/start` + `reset` used `rateLimit("signup")`). 5 reset attempts from an IP blocked real signups from that IP for 60s — a griefing vector. | New dedicated `password` limiter (10/min/IP) in `src/lib/ratelimit.ts`; both routes switched. |
| 2 | Medium | **Stale handle-availability state could wrongly block profile saves.** The settings form hard-failed on a client-side "taken" flag up to 400 ms old. | Client now blocks only on locally-knowable "invalid"; the server's uniqueness check (P2002 → 409) is the source of truth. |
| 3 | Medium | **Every public-profile view ran the same DB query twice** — `generateMetadata` and the page each called `getProfile()`. | Wrapped in React `cache()` → one query per request. |
| 4 | Medium | **Public profiles were fully dynamic** (`force-dynamic`): every view = full SSR + DB hits; no CDN caching. | Switched to ISR (`revalidate = 60`) + `revalidatePath()` fired from profile-edit and avatar-upload APIs, so pages are cached **and** edits show instantly. |

## 3. Performance optimizations SHIPPED (mobile + PC)

| # | Device | Change | Expected impact |
|---|---|---|---|
| 1 | Mobile | **Backdrop blur reduced on ≤768px** — `.glass/.surface/.eyebrow-glass` were `blur(10–18px) saturate(130–150%)` sitewide; mobile GPUs stall on this during scroll. Now `blur(8px)`, no saturate, on phones. | Biggest mobile win: smoother scrolling (jank → ~60fps), lower battery drain. |
| 2 | Mobile | **Lenis smooth-scroll disabled on touch devices** (`pointer: coarse`). Native momentum scroll takes over; the permanent rAF loop is gone on phones. | ~16 ms/frame of main-thread work freed; better INP. |
| 3 | Mobile | **Orbital particles 34 → 14 on phones** (each is an animated paint layer). Desktop unchanged. | Less paint cost in the ecosystem section. |
| 4 | PC | **Hero mouse-parallax rAF-throttled** — was doing a layout read + spring update per `mousemove` (120+/s on gaming mice); now max one per frame, cancelled on leave. | Lower INP under mouse movement. |
| 5 | Both | **Market ticker pauses in hidden tabs** (visibilitychange-aware; refreshes instantly when you return). | ~180 KB/hr data + battery saved per backgrounded tab. |
| 6 | Backend | **Dashboard: 3 user `count()` queries → 1 `groupBy`** (provider × membership buckets; totals derived). 7 → 5 queries per dashboard load. | Faster admin dashboard TTFB. |
| 7 | Backend | **Profile pages now CDN/ISR-cached** (see bug #4) — repeat views don't touch the DB for 60s. | TTFB ~50–100 ms better; DB load on hot profiles down ~100×. |

**Build before/after:** identical route sizes (159 kB shared JS) — all wins are runtime/paint/query-level, zero bytes added. Typecheck ✅ lint ✅ 50 tests ✅ build ✅.

## 4. Checked & found NOT to be issues
- `next/image` usage — every instance already has a correct `sizes` prop.
- JWT callback — DB refresh only fires on explicit `update()` or missing claims, not per-request.
- Research list/API caching — already correct (`revalidate 120` + `s-maxage=60, swr=300`).
- CSRF — handled by NextAuth; mutating routes all require a session.
- Comment deletion being admin-only — intentional moderation design.

## 5. Deferred (deliberate, with reasons)
| Item | Why deferred |
|---|---|
| Replace framer-motion (~35 kB gz) with CSS/IO animations | Touches every animated component; high regression risk for one-time ~80 ms FCP gain. Revisit if Lighthouse mobile < 85. |
| Cache `research/[slug]` pages | Premium gating needs the per-request session; caching would require splitting the gate client-side — a refactor, not a quick win. |
| Compress `logo.jpg` (93 KB original) | `sharp` not installed (no new deps policy); Vercel's image optimizer already serves AVIF/WebP variants, so real-world impact is minimal. Optional: re-export the JPG at ~50 KB whenever convenient. |
| Storage cleanup for orphaned uploads (deleted accounts' old avatars) | Cosmetic storage cost; needs a scheduled job. Fine to batch later. |
