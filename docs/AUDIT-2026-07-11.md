## 3. Tech stack

**Frontend:** Next.js 14 (App Router) · React 18 · TypeScript · Tailwind CSS
(custom gold/mint design system) · Framer Motion · Lenis (smooth scroll) ·
three.js + React-Three-Fiber + Drei (WebGL) · lucide-react + bespoke 3D SVG icons.

**Backend:** Next.js API routes (serverless, TypeScript/Node) · Prisma ORM →
Supabase Postgres · NextAuth (email+password, HMAC-OTP signup, Google, JWT) ·
Upstash Redis (rate-limits) · Resend (email) · Supabase Storage (uploads) +
Realtime (chat/DM) · web-push + VAPID (notifications) · Sentry (monitoring).

**Why one language (no Python):** this is a deliberate **full-stack TypeScript**
architecture — one language across front + back means shared types, fewer bugs,
faster iteration, and no separate server to run/pay for. Python would only add
value for heavy in-house ML/compute; here AI runs via external APIs (Gemini/Groq),
so it isn't needed. Big products (Vercel, Linear, Cal.com) use this same pattern.

**External services / APIs:** CoinGecko + CoinMarketCap + DefiLlama (market data) ·
Gemini + Groq (multi-provider AI, fallback order) · 25+ news RSS sources · Google
OAuth · Resend · VAPID push.

## 4. Architecture

- **Pages** render on the server, serialize, and hand off to `"use client"`
  components. ISR caching where safe (home 300s, research 120s, profiles 60s),
  dynamic where auth/personalization is needed.
- **Every API route** follows one pipeline: `rateLimit → zod-validate → auth-gate
  → prisma → handleError`. Consistency makes the code predictable and safe to extend.
- **Cached proxies** for third-party data (CoinGecko/DefiLlama/news) protect API
  keys and rate limits and keep the client fast.
- **Realtime** via Supabase broadcast (community chat + DMs), with a graceful
  poll fallback when realtime env is absent.

## 5. Security review — **8 / 10**

**Strong (verified in code):**
- Input validation with **Zod on every API body**; type-safety end to end.
- **Rate-limiting** (Upstash) keyed per action (signup/login/password/admin/…).
- **Auth gating** on every protected route; admin **permission system + audit trail**.
- **HMAC-hashed OTP** codes; server-side password policy; password-reset email check.
- Uploads verified by **magic-byte sniffing** (a renamed non-image is rejected).
- Secrets only in env (never in code/docs); user emails masked in public views.
- **Graceful degradation**: missing env/service never crashes the app.

**To improve (honest):**
- No formal third-party **penetration test** yet (recommended before a big launch).
- Some protections depend on **owner config** being present (Upstash for real
  rate-limits, etc.) — degrade to no-op if unset.
- Consider adding 2FA for admin accounts as the team grows.

## 6. Performance review — **7.5 / 10**

**Done:** ISR + cached API proxies · `next/image` optimization · code-split heavy
widgets (AI widget, smooth-scroll) · `optimizePackageImports` + `removeConsole` ·
`content-visibility` on homepage sections · mobile blur/animation trims · three.js
kept off the homepage · visibility-gated timers.

**Watch (honest):** the UI is animation-rich (a deliberate "premium" choice) — the
main cost on low-end mobiles. Inline data-URL images (zero-config upload path) add
payload at scale — configuring **Supabase Storage** upgrades those to CDN URLs.
Serverless cold starts + Supabase pooled connections are the usual scale limits.
